# Fase 09 — Expansão white-label

## Objetivo

Provar que uma segunda instituição pode ser incorporada sem fork e sem alterar regras específicas no core.

## Trabalho

1. Criar checklist de onboarding institucional.
2. Implementar novo adapter usando os mesmos testes contratuais.
3. Criar configuração, branding e scoring profile próprios.
4. Validar segregação de imagens, segredos, banco e backups.
5. Medir tempo e esforço de onboarding.
6. Automatizar provisionamento e upgrades de múltiplas stacks.
7. Avaliar necessidade real de control plane ou multi-tenancy.

## Gate

Segunda instituição implantada com zero fork, nenhuma regressão na ENS e documentação de onboarding reproduzível.
